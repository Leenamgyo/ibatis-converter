# The sample project

`src/interfaces/api/public/samples/` — what **Load sample** loads.
`manifest.json` lists the files; `app.js` fetches each one and runs the
normal analyze path, so the sample goes through exactly the same pipeline
as an uploaded mapper.

## It is a scenario matrix, not a demo app

One file per SQL shape, so a change to the graph or the converter can be
eyeballed against every shape in one pass:

| File | Covers |
|---|---|
| `common.xml` | shared `<sql>` fragments: pagination, active/soft-delete conditions, audit columns |
| `01-basic-select.xml` | plain SELECT, `#binding#` parameters, typed parameter, count, paging |
| `02-dynamic.xml` | `<isNotNull>` / `<isNotEmpty>` / `<isEqual>`, `<iterate>` IN list, nested dynamic, dynamic JOIN, dynamic UNION branch |
| `03-join.xml` | INNER / LEFT / RIGHT / FULL OUTER / CROSS / self join, a five-table chain, implicit comma join |
| `04-subquery.xml` | scalar subquery in SELECT, derived table in FROM, joined derived table, IN/EXISTS subquery, three-level nesting |
| `05-union-cte.xml` | UNION, UNION ALL with three branches, single and chained CTE |
| `06-refid.xml` | same-file include, cross-mapper include, nested include, and a deliberate circular pair |
| `07-resultmap.xml` | `resultMap`, `extends` chains, nested result mappings |
| `08-legacy-report.xml` | a realistic long report query — the size the UI has to stay readable at |
| `09-edge-cases.xml` | `$substitution$`, `<![CDATA[ ]]>`, comments, odd whitespace, a statement that fails to flatten |

## Load advanced

`samples/advanced/` is a second demo project, loaded by the **Load advanced**
button. It has its own `manifest.json` and `schema-mapping.json`, and the
변환 view offers that dataset with one click when this project is
open. It exists to show the hard cases working, not to be a scenario
matrix:

| File | Covers |
|---|---|
| `adv-00-common.xml` | Oracle ROWNUM paging head/tail fragments, a FROM-less column fragment, nested cross-namespace includes |
| `adv-01-mega-report.xml` | **one ~2000-line SELECT**: 38 CTEs (17 regions, 12 months), 160 joins, ROW_NUMBER, scalar/EXISTS subqueries, dynamic tags inside a CTE, UNION ALL totals. Generated by `test/fixtures/schema-migration/advanced/megaReport.js`; do not edit by hand |
| `adv-02-ibatis-syntax.xml` | `compareProperty`, `isParameterPresent`, `removeFirstPrepend`, `<dynamic open/close>`, `#p:VARCHAR:0#`, nested `<iterate>` with a conditional inside, CDATA, `$sortColumn$`, `TB_ORD_H_$yyyymm$`, `groupBy` + nested resultMap + nested select, `cacheModel`, `parameterMap` + `?`, selectKey post, Oracle `(+)` / CONNECT BY / DECODE / MERGE / INSERT ALL, `<procedure>` |

Unlike the basic sample, this one includes writes (INSERT/UPDATE/DELETE/
MERGE/procedure), because the hard syntax lives there.
`test/integration/advancedSample.test.js` pins it. The 2000-line query is
checked against the same query hand-written on the new schema, byte for
byte.

## SELECT only (basic sample)

Every statement in the basic sample is a SELECT. The tool is read at as a *lineage*
tool first, and an INSERT/UPDATE/DELETE in the sample makes the first
screen someone sees a write shape with no lineage to draw.

Write coverage is not lost — it lives in
`test/fixtures/write-statements/`, exercised by
`test/integration/writeStatements.test.js` (selectKey timing,
parameterMap, `INSERT … SELECT`, `<set>`, `{ call }`). The graph still
renders write statements; the samples just do not ship one.

The same rule applies to `test/fixtures/complex/` — 25 mapper files,
~1,500 lines, SELECT only, the scale test rather than the shape test. See
[../TESTING.md](../TESTING.md).

## Adding a scenario

Add the shape to the file that owns that category rather than starting a
new file, keep it a SELECT, and re-check the graph in a browser — the UI
has no automated test coverage.
